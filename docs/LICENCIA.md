# Elección de licencia

La licencia del código propio aún no fue elegida. Publicar un repositorio permite verlo y utilizar las funciones de GitHub correspondientes, pero no equivale a conceder una licencia general de redistribución o explotación del código. La elección debe ser expresa del autor.

| Opción | Idea principal | Cuándo considerarla |
|---|---|---|
| MIT | Reutilización amplia con conservación de avisos | Si se busca que otros puedan adaptar el código con pocas condiciones |
| Apache 2.0 | Permisos amplios y cláusulas adicionales, incluidas patentes | Si se prefiere una licencia permisiva más detallada |
| GPL | Distribución de derivados sujeta a las condiciones de la licencia | Si se busca reciprocidad al distribuir modificaciones |
| Decidir después | No añadir una licencia abierta todavía | Si se requiere revisar política universitaria o intención de publicación |

El código, la tesis, el logo y los datos pueden requerir decisiones diferentes. Una licencia del código no elimina atribuciones de mapas, librerías o documentos ajenos. No se elige una licencia en nombre del estudiante sin su indicación.

Referencia: [documentación de GitHub sobre licencias](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository). Resumen orientativo; consultar el texto de la licencia antes de elegirla.
